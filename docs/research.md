# Build two platforms, rent the other two

As of November 2026, a solo developer can build Instagram and YouTube Shorts entirely on the official APIs at no cost. TikTok and Snapchat are different: both block a personal app from posting publicly on its own, so the recommended architecture splits the dashboard by platform. Instagram's Graph API publishes Reels and **trial reels** (`trial_params`, added December 2025). It also handles comment moderation via webhooks and DM replies inside a 24-hour window, all at Standard Access with no App Review for an account you own. It has no scheduling, so your server has to fire each post. YouTube removed its last obstacles in 2026. Uploads now cost 1 unit from a dedicated 100-per-day bucket, uploads from unverified projects are **no longer locked to private (November 2, 2026)**, and `publishAt` gives native scheduling. TikTok's developer guidelines name "a utility tool to help upload contents to the account(s) you or your team manages" as an app type it will not approve. Snapchat's posting API is allowlist-only. Both platforms therefore need either a middleman that already holds approved access, or a phone handoff where you tap "post." Under $20/month, the strongest middleman candidate is Zernio (formerly Late). Its conflicting pricing sources put two accounts anywhere from **$0 to $33/month**, so confirming that price is the single most important thing to check before building. Hosting fits the budget only barely: Cloudflare R2 storage with **zero egress** costs about nothing, but Vercel's free crons run once a day, and Hetzner's €5.99 VPS has often been out of stock since its June 2026 repricing. One more limit applies everywhere: no platform's posting API can attach trending library audio. Any post whose reach depends on a trending sound has to be finished in the native app, whatever the architecture.

## Instagram and YouTube give a solo developer almost everything free

### Instagram publishes trial reels but makes your server hold the clock

Instagram offers three login flavors. **Instagram Login** (`graph.instagram.com`, scopes `instagram_business_basic` + `instagram_business_content_publish`) needs no Facebook Page. **Facebook Login** needs a linked Page and adds resumable binary upload. A newer Unified Login uses system-user tokens. An app must pick Instagram Login or Facebook Login, not both ([Meta: Content Publishing](https://developers.facebook.com/documentation/instagram-platform/content-publishing.md); [Meta: App Review](https://developers.facebook.com/documentation/instagram-platform/app-review)). Publishing takes three steps: create a container with `media_type=REELS` and a public `video_url`, poll `status_code` until `FINISHED` (Meta suggests once a minute for up to five minutes), then call `media_publish`. **Containers expire after 24 hours**, and an account can create 400 per rolling day ([Meta: IG User Media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media.md)). Meta's docs never mention a schedule parameter, and an August 2026 integrator guide says plainly that "there is no `scheduled_publish_time` equivalent," so the app must create and publish each container at fire time ([bundle.social](https://bundle.social/blog/instagram-graph-api)). The publishing cap is listed as **100 posts per rolling 24 hours** in one section of Meta's page and 50 in another ([Meta: Content Publishing](https://developers.facebook.com/documentation/instagram-platform/content-publishing.md)), and Ayrshare plans around 50 ([Ayrshare](https://www.ayrshare.com/docs/apis/post/social-networks/instagram.md)). Either way, four a day never comes close.

Reels can run 3 seconds to 15 minutes, up to 300 MB, at 23–60 fps. `cover_url` sets a custom 9:16 JPEG cover, `share_to_feed` controls Feed placement, `collaborators` accepts up to three handles, and captions allow 2,200 characters and 30 hashtags ([Meta: IG User Media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media.md)). Trial reels arrived on December 3, 2025 as `trial_params.graduation_strategy` with two values. `MANUAL` means the reel "is graduated manually in the native Instagram app." `SS_PERFORMANCE` means it auto-graduates if it performs well ([Meta Dev Blog](https://developers.facebook.com/blog/post/2025/12/03/instragram-api-updates/); [Meta: IG User Media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media.md)). **No endpoint exists to graduate a trial or read its trial status**, which Ayrshare's docs confirm ([Ayrshare](https://www.ayrshare.com/docs/apis/post/social-networks/instagram.md)). Your planned flow, where the weekly report recommends which trials to share and you approve, therefore ends with a manual tap in the Instagram app. The dashboard can produce the checklist but cannot do the sharing. Eligibility is the second catch. Instagram decides at publish time whether the account can post trials, so an ineligible trial fails outright ([Planoly](https://www.planoly.com/blog/can-you-schedule-trial-reels)). bundle.social's docs suggest roughly **1,000 followers**, note some users got access at 200, and warn "not every professional account gets this feature" ([bundle.social API reference](https://info.bundle.social/api-reference/platforms/instagram)). For an account about a month old, the scheduler needs an explicit fallback rule: either retry as a normal reel or flag the post.

Engagement is well supported. On your own media you can list comments, reply, hide, delete and toggle comments, with real-time `comments` webhooks that Meta recommends over polling. **Standard Access is sufficient** for accounts you own ([Meta: Comment Moderation](https://developers.facebook.com/documentation/instagram-platform/comment-moderation.md)). Private replies to commenters are capped at 750 per hour ([Meta: rate limiting](https://developers.facebook.com/documentation/business-messaging/messenger-platform/overview/rate-limiting)). DMs arrive by webhook and can be answered, but **only within 24 hours of the user's last message**. The app can never open a conversation. A 7-day Human Agent window exists, but it is a separately reviewed feature for apps with a custom inbox. API-received messages also stay unread in the Instagram app until you reply, so the dashboard becomes the source of truth for unread threads ([Meta: Messaging API](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/messaging-api.md); [Meta: Messaging App Review](https://developers.facebook.com/documentation/business-messaging/instagram-messaging/app-review/apps-for-your-own-business)). Meta's review table lists App Review as "Not required" for an app serving only a business you own ([Meta: App Review](https://developers.facebook.com/documentation/instagram-platform/app-review)). That matters for the January deadline, because review per permission otherwise runs **2–4 weeks** ([Postproxy](https://postproxy.dev/blog/instagram-reels-api-publishing-guide/)). The design consequence: your drafted-DM queue needs a visible countdown on each thread's 24-hour window, because a reply drafted Sunday for a Friday message can no longer be sent.

Reels insights include `views`, `reach`, `saved`, `shares`, `ig_reels_avg_watch_time`, the new **`reels_skip_rate`** (share of views skipped within 3 seconds), `reposts` and `crossposted_views`. They **do not include per-reel `follows` or `profile_visits`**. Data lags up to 48 hours, and Instagram Login apps get no insights webhooks ([Meta: Media Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights.md); [Meta Dev Blog](https://developers.facebook.com/blog/post/2025/12/03/instragram-api-updates/)). Some account metrics, including `follows_and_unfollows`, are withheld from accounts under 100 followers ([Meta: Account Insights](https://developers.facebook.com/docs/instagram-platform/api-reference/instagram-user/insights)). No documentation says whether ungraduated trials return insights or split follower from non-follower views. That is the biggest unknown for the "which trials to share" report, and it should be tested in week one. Audio is a hard wall. `audio_name` renames only original audio, and Instagram's music library cannot be attached through the API ([Meta: IG User Media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media.md); [Postproxy](https://postproxy.dev/blog/instagram-reels-api-publishing-guide/)). A trending song baked into the file posts as original audio, so the reel is not attached to that song's audio page. That attachment is most of the point of using a trending sound.

### YouTube's 2026 changes removed every solo-creator blocker

YouTube's revision history records three changes that reverse most older write-ups. **December 4, 2025:** upload cost fell from about 1,600 units to about 100. **June 1, 2026:** `videos.insert` and `search.list` moved into their own buckets of 100 calls per day at 1 unit each. **November 2, 2026:** uploads from unverified projects "are no longer restricted to private viewing mode," ending the 2020 lock ([YouTube revision history](https://developers.google.cn/youtube/v3/revision_history?hl=en); [YouTube quota](https://developers.google.cn/youtube/v3/getting-started?hl=en)). On November 3, 2026, `thumbnails.set` gained custom Shorts thumbnails ([revision history](https://developers.google.cn/youtube/v3/revision_history?hl=en)). Scheduling is native: `videos.insert` accepts `status.publishAt` and returns `invalidPublishAt` for bad times ([videos.insert](https://developers.google.cn/youtube/v3/docs/videos/insert)), so YouTube holds the clock and your server does not. The API has no "isShort" flag ([videos.insert](https://developers.google.cn/youtube/v3/docs/videos/insert)); YouTube classifies a Short from the file itself. Comments are fully supported. Listing threads costs 1 unit and each reply (`comments.insert`) or moderation action costs 50 from the 10,000-unit daily pool ([quota calculator](https://developers.google.cn/youtube/v3/determine_quota_cost?hl=en)), enough for roughly 190 auto-replies a day. Analytics expose `engagedViews`, `averageViewDuration`, `averageViewPercentage`, `subscribersGained` and `shares` ([YouTube Analytics metrics](https://developers.google.com/youtube/analytics/metrics.md)), and the June 2026 `videos.batchGetStats` pulls public stats cheaply ([revision history](https://developers.google.cn/youtube/v3/revision_history?hl=en)). The remaining friction is OAuth. A project in "Testing" status gets **7-day refresh tokens**, while an unverified app set to "In production" shows a warning screen and is capped at 100 users ([Google OAuth](https://developers.google.cn/identity/protocols/oauth2/production-readiness/overview)). For one user, publishing unverified avoids weekly re-logins. One caveat on sourcing: Google's English developer pages were unreachable during research, so these YouTube facts come from Google's official .cn mirror and should be re-read on developers.google.com before you write code against them.

## TikTok and Snapchat reserve public posting for approved partners

TikTok's Content Posting API offers **Direct Post** (`video.publish`) and **Upload-to-Inbox** (`video.upload`, where the video lands as a draft you finish in the app) ([TikTok Get Started](https://developers.tiktok.com/docs/en/content-posting-api-get-started)). Unaudited apps can post only to **private accounts with `SELF_ONLY` visibility, for at most 5 users a day**. Posting to a public account fails with `unaudited_client_can_only_post_to_private_accounts` ([TikTok Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines); [Direct Post reference](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post)). The audit itself excludes you. TikTok states "Apps must not be for private or personal use" ([App Review Guidelines](https://developers.tiktok.com/docs/en/app-review-guidelines)) and lists both "a utility tool to help upload contents to the account(s) you or your team manages" and "an app that copies arbitrary contents from other platforms to TikTok" as unacceptable ([Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines)). Your dashboard matches both descriptions exactly. Even audited apps face strict UX rules: fetch `creator_info` before every post, have the user pick privacy from a dropdown "with no default value," keep duet, stitch and comment toggles unchecked by default, show TikTok's Music Usage Confirmation, and send only after the user "has expressly consent[ed] to the upload" ([Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines)). The API has **no sound parameter and no scheduled-time field**. The per-creator cap is about 15 posts a day, and init calls are limited to 6 per minute per token ([Direct Post reference](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post)). Posts made while unaudited reportedly stay private even after a later audit, and they fail silently to private rather than erroring ([bundle.social](https://bundle.social/blog/tiktok-api-approval)).

That leaves three TikTok paths. The first is a middleman with an audited app. The second is a self-built Upload-to-Inbox flow, where Postiz's docs say drafts must be finished within 24 hours ([Postiz TikTok docs](https://docs.postiz.com/providers/tiktok.md)), meaning four phone handoffs a day. The third is posting natively. The inbox path does carry one real advantage: you finish the post in TikTok's editor, which is presumably where a trending sound can be added, though no source confirmed this. Comments and DMs are thinner still. The consumer API has no verified comment-reply or DM endpoints. TikTok's separate API for Business advertises "community interaction" and a Business Messaging API with automated replies, but its eligibility and endpoints were not verified ([TikTok API for Business](https://ads.tiktok.com/help/article/marketing-api?lang=en)). In practice, TikTok comment automation comes through a middleman: bundle.social's automations can reply to and like TikTok comments but cannot send TikTok DMs ([bundle.social pricing](https://bundle.social/pricing.md)).

Snapchat does have a real posting API, the **Public Profile API**. It handles chunked uploads (up to 1 GB), Stories, Saved Stories and Spotlights, and Spotlight posts move through `SUBMITTED`, `LIVE` or `REJECTED` review ([Snap: Asset Management](https://developers.snap.com/marketing-api/Public-Profile-API/ProfileAssetManagement)). But "the Public Profile API is currently allowlist only." Access requires emailing "your Snap contact" an OAuth client ID created in Ads Manager, not the Developer Portal ([Snap: Get Started](https://developers.snap.com/marketing-api/Public-Profile-API/GetStarted)), and Snap publishes no criteria for approving individual creators. The open alternative is **Creative Kit**, which hands media and a caption to Snapchat's camera or preview so the user can send it to Story or Spotlight ([Snap: Creative Kit](https://developers.snap.com/snap-kit/creative-kit/overview)). It pre-fills the post but does not publish it, and its stated video limits mention splitting into Snaps of 10 seconds or less. That could break Spotlight videos, so test it on your iPhone before relying on it. Snap's Terms (effective September 21, 2026) forbid "automated or semi-automated means" and third-party apps that interact with the Services without written consent ([Snap Terms](https://www.snap.com/terms?lang=en-GB)), which rules out browser automation as a workaround. The research found no public API for Snapchat comments.

The table shows why one vendor decides the budget. Only Zernio could plausibly cover TikTok and Snapchat together for $20 or less. Under the per-account model, sending just those two platforms through it would land inside the free tier. Under the October 2025 tiers, 240 combined posts a month would push you to the $33 Accelerate plan. Full schedulers are mostly a poor fit for this workload. Publer (about $5–10 per account per month) and Buffer ($5–6 per channel) are the only mainstream tools whose four-account price lands near $20 ([poster.ly](https://www.poster.ly/guides/cheapest-social-media-scheduler-2026); [hashtagtools](https://hashtagtools.io/blog/buffer-vs-later-vs-metricool-best-scheduler-2026)). Neither confirms Snapchat, and either one would consume the entire budget with nothing left for a server. Publer's API also sits on its Business tier. Snapchat publishing appears only in pricier tools such as Vista Social ($64–99, with sources disagreeing), Later and OneUp ([Zapier](https://zapier.com/blog/best-social-media-management-tools/); [Sked Social](https://skedsocial.com/blog/schedule-snapchat-posts)). Later's trial-reel support also requires 1,000+ followers ([Planoly](https://www.planoly.com/blog/can-you-schedule-trial-reels)). Hootsuite, Sprout and Agorapulse start around $99 per user per month ([Zapier](https://zapier.com/blog/best-social-media-management-tools/)), which is enterprise pricing.

These products are better as feature blueprints, and each contributes a specific pattern. **Publer** shows trial reels as a per-post toggle with an auto-share or manual choice ([Publer](https://publer.com/blog/best-tools-to-schedule-instagram-trial-reels/)). **Buffer's** Create Space provides an idea backlog and push reminders for posts that need native audio ([Buffer](https://buffer.com/resources/instagram-trending-reels/)), which is exactly the right workaround for the audio wall. Buffer also rewrites one post per platform with AI, and **Later** offers a drag-and-drop visual grid ([hashtagtools](https://hashtagtools.io/blog/buffer-vs-later-vs-metricool-best-scheduler-2026)). **Metricool** does competitor benchmarking, and **Agorapulse** has the strongest unified inbox ([Zapier](https://zapier.com/blog/best-social-media-management-tools/)). From comment-to-DM tools like **ManyChat**, **LinkDM** and **ohyap** ($0–19/mo), copy three habits: trigger only on inbound engagement, send one private reply per comment, and pause automation once a human replies. Avoid identical copy-paste blasts, which can get accounts limited ([ohyap](https://ohyap.com/best-instagram-automation-tools)). That warning matters for your hate-comment replies, so have Claude vary the wording each time. **Submagic's** animated captions, silence and bad-take removal and auto-zoom are the touch-up features worth rebuilding. Clipping and virality scores matter little for content that is already short ([Ssemble](https://www.ssemble.com/blog/best-ai-clipping-tools-2026)). The most valuable pattern is DOHOO's reliability discipline: store a preflight record with a consent timestamp and `publish_id`, poll with bounded retries, and treat a timeout as "unknown" rather than resubmitting, so you never double-post ([DOHOO](https://blog.dohoo.ai/blog/tiktok-content-posting-api/)). Blotato's docs make the same point: "an accepted submission isn't proof of publication" ([PlugKit](https://www.plugkit.co/blog/blotato-pricing-api-alternatives/)).

On the open-source side, **Postiz** is the closest architectural twin: a Next.js frontend, NestJS backend, Prisma/Postgres, Temporal workflows and Redis. It covers Instagram, YouTube and TikTok but **not Snapchat**, and you still need your own platform apps and approvals ([Postiz README](https://cdn.jsdelivr.net/gh/gitroomhq/postiz-app@main/README.md)). Its license is AGPL-3.0. Since you may monetize later, study its per-platform provider modules and TikTok handling and re-implement them instead of copying files, because AGPL's network clause would apply to a future SaaS. **Mixpost** is MIT-licensed but written in PHP/Laravel ([GitHub](https://github.com/inovector/mixpost)), so it is only useful as reading material. Popular **n8n** posting templates call Upload-Post's paid API rather than the official APIs ([n8n workflow 2894](https://n8n.io/workflows/2894-upload-to-instagram-tiktok-and-youtube-from-google-drive/)), so they add no free path.

## A six-euro server and free R2 storage barely fit $20

Storage is the easy part. Cloudflare R2 charges $0.015 per GB-month after a free 10 GB, and **egress is free** ([Cloudflare R2](https://developers.cloudflare.com/r2/pricing)). That matters because Instagram (`video_url`), TikTok (`PULL_FROM_URL`, which requires a verified domain) and every middleman fetch media from a public URL ([Meta: IG User Media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media.md); [Direct Post reference](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post)). At 28 videos a week of 50–100 MB, you upload about 6–12 GB a month. Keeping 30 days of masters stays inside the free tier, and keeping everything forever reaches about $2 a month after a year. The roughly 25–50 GB of monthly platform fetches cost nothing on R2 but would be the main cost risk on S3 or Vercel bandwidth. Serve the bucket from a custom domain so TikTok can verify it, which Postiz's docs also recommend ([Postiz TikTok docs](https://docs.postiz.com/providers/tiktok.md)).

Compute is the tight part. **Vercel Hobby crons run at most once a day with ±59-minute precision**, and more frequent schedules fail to deploy ([Vercel](https://vercel.com/docs/cron-jobs/usage-and-pricing)). That cannot fire four Instagram posts a day at chosen times. Hetzner's CX23 (2 vCPU, 4 GB) lists at €5.99 with IPv4, but it is EU-only and was **not orderable on four checks between September and October 2026**. The orderable CPX22 costs €19.99, and US CPX11 costs about $20.49 ([Bitdoze](https://www.bitdoze.com/hetzner-cloud-cost-optimized-plans/)), following a June 2026 repricing with "limited availability" notices ([Findstack](https://findstack.com/resources/hetzner-price-increase-2026)). Either of the orderable plans uses the whole budget. Prices for DigitalOcean, Railway, Render and Fly.io were not verified. A ~$5 VPS from any provider fits the plan; a $20 one does not.

The per-platform split reduces what the server must do. YouTube holds its own schedule via `publishAt`, and middlemen hold theirs. So the always-on box only fires Instagram publishes, receives Instagram comment and DM webhooks, polls YouTube comments and insights, and serves the phone UI. A Postgres-backed queue such as pg-boss or a polled `scheduled_posts` table is enough at this scale; Postiz's Temporal-plus-Redis stack is overkill for one user on a small VPS. The heavy work (Whisper captions, ffmpeg trims, format checks) can run on your Windows laptop during the weekly batch, with finished files uploaded to R2. That keeps the server to a 2 vCPU, 4 GB size. If no cheap VPS can be ordered, the fallback is Vercel Hobby for the UI and webhook routes plus an external pinger that hits a "publish due posts" route every few minutes. That setup was not priced in this research.

## Recommended architecture: four providers behind one queue

| Platform | Route | What's automated | What stays manual | Cost |
|---|---|---|---|---|
| **Instagram** | Build: Graph API, Instagram Login, R2 URLs | Reels and trial reels at fire time, comment auto-replies and hiding, DM inbox with drafts, insights polling, creator tracking via Business Discovery | Sharing MANUAL trials to followers; trending-audio posts; sending DM drafts (your choice) | $0 |
| **YouTube Shorts** | Build: Data API + Analytics API, unverified app in "production" | Upload with `publishAt`, Shorts thumbnails, comment replies (50 units each), analytics | None required | $0 |
| **TikTok** | Rent: Zernio, or Upload-Post if Zernio fails checks; fallback is self-built inbox drafts | Public posting at scheduled times; comment replies where the vendor supports them | Trending sounds; DMs | $0–16 |
| **Snapchat Spotlight** | Rent if Zernio's Snapchat support is real; otherwise a Creative Kit phone handoff | Posting (vendor) or pre-filled share sheet (handoff) | Analytics (in-app Insights); the tap to post under the handoff | $0–12 |

Choose Instagram Login over Facebook Login. Facebook Login's main advantage is resumable upload, and the R2 bucket you need for TikTok makes that irrelevant. Its other extras (media deletion, `total_views`, paid-partnership flags) do not matter in v1 ([Meta: Content Publishing](https://developers.facebook.com/documentation/instagram-platform/content-publishing.md); [Meta Dev Blog](https://developers.facebook.com/blog/post/2025/12/03/instragram-api-updates/)). Default trials to `MANUAL`, so the weekly report keeps your approve-then-share loop, and offer `SS_PERFORMANCE` per post as the hands-off option. Build every provider behind one interface (`prepare`, `publish`, `pollStatus`, `fetchComments`, `reply`, `fetchMetrics`) so a vendor can be swapped for a direct integration later. Above all, keep one canonical `post` record per video per platform, with its approval timestamp. That record is what TikTok's consent rules ask for in spirit ([Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines)), and your one weekly approval sitting can stamp all 112 posts at once.

The research branch needs careful scoping, because none of Instagram's trend surfaces (the professional-dashboard Inspiration tab, Reels Trends, Edits' Inspiration feed) has a known public API. TikTok Creative Center publishes regional trend charts for sounds and hashtags ([Buffer](https://buffer.com/resources/instagram-trending-reels/)). For creator tracking, Instagram exposes `view_count` through Business Discovery ([Meta Changelog](https://developers.facebook.com/docs/instagram-platform/changelog)), and YouTube's `search.list` has its own 100-call daily bucket ([YouTube quota](https://developers.google.cn/youtube/v3/getting-started?hl=en)). Plan for Claude to digest those feeds plus trends you capture by hand into an idea backlog, rather than promising automated trend scraping. Scraping would break both Meta's and Snap's terms. Store OAuth tokens and vendor API keys encrypted at rest in Postgres, keep them server-side only, refresh them from the worker before expiry, and lock the dashboard behind a passkey or a single-email login. No platform source covered token storage; these are standard practice.

Some items should be checked in the first week, before deeper building, because each one changes the design: Zernio's live pricing, its Snapchat status, and whether its TikTok posts land public; whether Instagram lets your account post trials yet, and whether trial insights come back; whether Creative Kit on iPhone can send a full-length video to Spotlight; YouTube's November 2026 changes on the English docs; and whether a ~$5 VPS can actually be ordered. One risk stays open: no source measured whether API-posted content reaches fewer people than natively posted content on any of the four platforms.

## Conclusion

The central insight is that "automation" means different things on each platform, and the boundary is set by policy, not engineering. Meta and Google now treat a single-owner app as a first-class citizen. TikTok and Snap deliberately route individuals through partners, and TikTok's audit rules specifically exclude self-use cross-posting tools. A personal dashboard therefore cannot be one integration repeated four times. It is a scheduler with two native providers, one or two rented ones, and a phone-handoff mode as a permanent fixture rather than a temporary hack. The handoff mode stays necessary even where APIs work, because trending audio and trial graduation both remain in-app actions.

For the January deadline, the order of work follows from where approvals and uncertainty sit. Instagram and YouTube need no review and can be built immediately. TikTok and Snapchat depend on a vendor whose pricing and coverage must be verified first, so verify that vendor before writing those providers. If Zernio holds up, the full system runs on about $7–20 a month. ### Metrics response shapes (2026-11-11, docs only, no API calls)
- **Instagram media insights** (https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights): `GET /{media-id}/insights?metric=…` → `{ data: [{ name, period, values: [{ value }], title, description, id, total_value?: { value, breakdowns? } }] }`. `value` is an Integer; `period` is always `lifetime` for media. `ig_reels_avg_watch_time` = "average amount of time spent playing the reel" (**Meta's page gives no unit**; Zernio's analytics schema says **milliseconds**). `reels_skip_rate` = **percentage** of initial views skipped in the first 3 s. `ig_reels_video_view_total_time` and `views` are labelled "in development"; `reach` is "estimated".
- **IG Media fields** (https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media): `like_count` (excludes promoted; **omitted when the owner hides likes**), `comments_count` (includes replies). `total_like_count` / `total_comments_count` add promoted/boosted surfaces (FB Login only). We use the organic counts.
- **YouTube** (https://developers.google.com/youtube/v3/docs/videos): `videos.list?part=statistics&id=…` → `items[].statistics.{viewCount, likeCount, commentCount}` as **strings** (unsigned long); `dislikeCount` owner-only; `favoriteCount` always 0. **Watch time isn't in the Data API.** It needs the YouTube Analytics API (https://developers.google.com/youtube/analytics/metrics: `averageViewDuration`, seconds; `estimatedMinutesWatched`; `averageViewPercentage`) and the `yt-analytics.readonly` scope.
- **Zernio** (https://docs.zernio.com/products/analytics.mdx, https://docs.zernio.com/analytics/get-analytics.mdx): `GET /v1/analytics?postId=…` (Zernio, external or native id) → `analytics` (PostAnalytics: impressions, reach, likes, comments, shares, saves, clicks, views, follows, `igReelsAvgWatchTime` ms, …) + `platformAnalytics[]` per platform with its own `analytics` and `syncStatus`. TikTok post metrics: **likes, comments, shares, views** ("more on Business app connections"). `202` = still syncing. **`402` = "Analytics add-on required" on legacy plans; usage-based plans include it.** Which plan our account is on isn't confirmed.
