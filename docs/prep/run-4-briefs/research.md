# Brief: Research that runs itself (backend + data layer)

Read `docs/prep/run-4-agent-rules.md` (binding), `CLAUDE.md`, `docs/decisions.md` §4 (AI split), `docs/voice.md`, `.claude/skills/research-brief/`. You do not commit.

## Goal
Tracked creators stay manual (add / remove). **Ideas and Hooks become automatic and recurring**, pulled from the tracked creators through Instagram Business Discovery (official API, already in `packages/research/src/discovery.ts`) and from his own niches. Each idea shows: the reference video link, what it's about, how to adapt it without copying, and a "Used" checkbox that moves it to an "Already used" archive. The 20 yap scripts in `docs/content/week-2026-11-16/yap-scripts.md` are imported as ideas. It must work end to end on the seed data with zero effort from him.

## Decision already made by the lead (record it in `docs/decisions.md` as a dated addendum to §4, do not rewrite §4)
- Generation runs as a **worker job** (`research-refresh`, every 3 days, plus once at worker start if it never ran), because the server is always on and the laptop is not.
- The job needs **no AI** to produce useful ideas: ranking and the "about / adapt" text come from code (see below). Cost: zero.
- Optional **AI notes** (Haiku rewrites "what it's about" and "how to adapt it" in his voice) are behind a setting `research.aiNotes`, **default off**, with a hard monthly token budget (`research.aiMonthlyTokens`, default 300 000 tokens ≈ well under $1 at Haiku prices; verify the current price from the Anthropic pricing docs or `docs/research.md` and state the number you used) counted in a DB table. When the budget is used up the job silently falls back to the code-written notes. Turning it on is budget-affecting, so the Settings page shows it as "Needs your OK in chat"; the worker also requires the env `RESEARCH_AI_NOTES=1` in addition to the setting.
- No copying: stored text from other creators is limited to the first line of their caption (the hook, ≤ 140 chars) shown as a quoted, attributed reference; never their full caption, never their video file or thumbnail. Ideas link out to the reference.

## Build
1. **Migration `0013_research_auto.sql`** (additive, re-runnable):
   - `ideas`: `source text not null default 'manual'` (check in 'manual','creator','niche','script'), `source_key text` + partial unique index (idempotent upserts), `reference_url text`, `about text not null default ''`, `adapt text not null default ''`, `used_at timestamptz`, `pattern text`, `score numeric`, `notes_by text not null default 'code'` (check in 'code','ai','manual').
   - `hooks`: `source_key text` + partial unique index, `reference_url text`, `pattern text`, `template text not null default ''`, `used_at timestamptz`; widen the `source` check to add `'niche'`, `'script'`.
   - `creator_media` (creator_id fk, platform_media_id, permalink, kind, hook_line text, like_count, comments_count, published_at, first_seen_at, last_seen_at; pk (creator_id, platform_media_id)): the minimum needed to rank; no full captions, no media URLs.
   - `research_runs` (id, started_at, finished_at, status, creators_checked, ideas_added, hooks_added, note) and `ai_token_usage` (month date, purpose text, input_tokens bigint, output_tokens bigint; pk (month, purpose)).
2. **Pure core** in `packages/research/src/auto/` (tests first):
   - `rankMedia(snapshot)`: per creator, score = engagement (likes + comments) relative to that creator's median over the fetched window, recency-weighted; keep the top 3 per creator per run that we haven't turned into ideas yet.
   - `hookLine(caption)`: first sentence/line, cleaned of hashtags, @mentions, links and emoji runs; ≤ 140 chars; `null` when nothing usable. Run the privacy lint (`lintText`) on it; a line that fails the location lint is dropped (never store a place name).
   - `classifyPattern(hookLine)`: reuse the existing hook-pattern classifier if one exists (`brief.ts`, `backlog.ts`, or the analytics package); else a small rule set: question, number/list, contrarian ("stop doing…", "X is a lie"), story ("I used to…"), how-to, challenge/day-N, result-first.
   - `aboutFromCode(media, creator)` and `adaptFromCode(pattern, pillar)`: plain sentences. About = "A <kind> by <creator display name> that opens with a <pattern> hook: “<hook line>”. It got <x>× their usual engagement." Adapt = a pattern-specific instruction that keeps the *structure* and replaces the *substance* with his own, e.g. question → "Open with your own question about <pillar topic> that your viewer already half-believes; answer it from your own training/trading week. Don't reuse their wording or example." Write one good, specific template per pattern × pillar (gym, trading, other), in the calm voice of `docs/voice.md`.
   - `nicheIdeas(pillars, weekSeed)`: a rotating, deterministic set of evergreen idea prompts per pillar (at least 30 per pillar in a data file `packages/research/data/niche-prompts.json`, written by you in his voice: gym = process, consistency, form, recovery; trading = his own process and psychology only, no tickers, no setups, no return claims, per the compliance note in the yap scripts file). 3 new per run, never repeating one already present (`source_key`).
   - `parseYapScripts(markdown)`: parses the file format (`## #N · Lane: title`, **Hook**, **Alt hook**, **Anchor**, **Close**, the script between the `<!-- script -->` marker and the next heading). → ideas with `source='script'`, `stage='scripted'`, title, hook, script, pillar from the lane, `about` = the anchor line without the URL, `reference_url` = the anchor's source URL when present, `adapt` = '' (it is already his). Alt hooks → hooks rows with `source='script'`. Idempotent via `source_key = 'yap-2026-11-16-#N'`.
   - Budget guard `canSpend(usage, budget, estimate)` and the Haiku note writer behind an interface (real one in a separate file using the existing Anthropic client conventions in `packages/engagement/src/triage-anthropic.ts`; a fake for tests). The AI prompt forbids quoting more than the hook line, forbids places, and its output passes `lintText` + voice lint or is discarded in favour of the code text.
3. **Worker job** `apps/worker/src/jobs/research-refresh.ts` (+ registration): for each active creator call Business Discovery (bounded: at most 10 creators per run, existing limit per creator; a failed creator is skipped with one line in `research_runs.note`; rate-limit ends the run cleanly) → upsert `creator_media` → rank → insert ideas (`source='creator'`) and hooks (pattern + `template` = the fill-in structure, `text` = the quoted reference hook, attributed) → niche ideas → optional AI notes within budget → write the `research_runs` row. With no Instagram credentials configured it still does the niche and script parts and says so in the run note. Dry-run safe (it only reads from the platform and writes to our own tables; that is allowed in dry-run, same as analytics ingest: check how `analytics-ingest` treats DRY_RUN and follow it).
   - Script import: bundle the parsed scripts as `packages/research/data/yap-2026-11-16.json` generated by a small script `scripts/research/build-yap-data.ts` from the markdown (commit both); the job upserts them on every run (idempotent). Before bundling, run the leak scanner (`node scripts/check-public-leaks.mjs`) and the location lint over the JSON.
4. **Store + web data layer**: extend `packages/research/src/store.ts` and add `apps/web/lib/research/ideas.ts`: `loadIdeas(pool, { tab: 'ideas'|'used', pillar?, source? })`, `markIdeaUsed(pool, id, used: boolean)`, `loadHooks(pool, { used? })`, `markHookUsed`, `loadCreators`, `addCreator`, `removeCreator` (= set inactive, existing function), `loadResearchStatus(pool)` (last run, next run, counts, AI notes on/off and tokens used this month). Server actions for these in `apps/web/app/research/actions.ts` (keep existing ones compiling). Pages are rebuilt by a designer: do not restyle pages; only keep them compiling.
5. **Seed** (`scripts/dev/lib/seed-research.ts` + one line in `scripts/dev/seed.ts`): run the real pipeline against a fixture Business Discovery response for the 3 seeded demo creators (fake handles), so the seed DB ends up with ~9 creator ideas with reference links (use `https://www.instagram.com/reel/DEMO<n>/` style obviously-fake permalinks), 3 niche ideas, the 20 script ideas, a few used ones, and hooks. This is also the end-to-end test: a `.db.test.ts` that runs the job twice against the fixture and asserts no duplicates and the expected counts.
6. Update the research-brief skill text only where the workflow changed (ideas now arrive by themselves; the skill is for a deeper, on-demand brief).
