# F20: Inbox-first notifications, replies drafted on every platform, touch-up that settles, daily Instagram, reel maker

Status: spec, 2026-11-22. From the creator's phone use after F19.

## Audit (root causes, verified by scouts)
- **Stacked "N need you" rows**: the hourly reply-ping digest inserts a new `alerts` row (`kind reply-ready`, `comment_id null`) every hour and never closes old ones (`apps/worker/src/jobs/engagement-store.ts:516-518`, `packages/engagement/src/pings.ts:72-92`). Pop-over = newest 6 open alerts with only Acknowledge (`components/ui/NotificationsPopover.tsx:50-91`, `components/AppFrame.tsx:49-53`). These rows duplicate Inbox state.
- **No drafts anywhere**: without `ANTHROPIC_API_KEY` the worker uses `createFakeTriageClient(FLAG_ALL_RULES)` (`apps/worker/src/jobs/register-engagement.ts:52-60`): every non-rule comment is flagged, none drafted. Drafted = `engagement_actions.status='shadow'` (`apps/web/lib/inbox/list.ts:75`).
- **YouTube comments never polled** unless `YT_CHANNEL_ID` is set (`packages/adapters/src/comments/index.ts:33-34`); the creator's env has the OAuth vars but not that one.
- **TikTok comments**: stub (`packages/adapters/src/comments/tiktok.ts:10-26`), mode default off.
- **Touch-up refills**: `media-recheck` re-QAs only 5 legacy rows / 10 min (`apps/worker/src/jobs/media-recheck.ts:34-40`), so new flagged clips keep appearing after "Keep all"; unfixable issues (`frozen-middle`, `black-middle`, `too-long`, `landscape|square|tall`; `qa-types.ts:50-61`) sit in the list with nothing to do.
- **Few Instagram posts**: nothing tops up Instagram daily; weekly-draft is Sunday-only with empty captions, which block approval.

## Streams
### A. Notifications = events, Inbox = work (Sonnet)
Files: `packages/engagement/src/pings.ts`, `apps/worker/src/jobs/engagement-store.ts` (ping writes only), `apps/worker/src/jobs/engagement-triage.ts` (ping call only), `apps/web/lib/alerts/*`, `apps/web/components/ui/NotificationsPopover.tsx`, `apps/web/components/AppFrame.tsx`, `apps/web/components/frame-counts.ts`, `apps/web/components/notifications/*`, `apps/web/app/notifications/page.tsx`, `apps/web/lib/inbox/*` (read helpers only), tests.
- Worker: the digest **upserts one open row per platform** (`reply-ready`, `comment_id null`, `platform = <platform>`): update message/created_at of the open one, insert only if none; per-platform counts in `pingState`. Text: "7 replies drafted to your Instagram comments" / "3 Instagram comments need you". Per-item pings unchanged (they carry `comment_id`). Push behaviour unchanged.
- Web: `loadInboxGroups(pool)` → per platform `{ drafted, needsYou, dmsOpen, newest: { id, authorHandle, text, at } }` from the Inbox queries (`lib/inbox/list.ts`). Pop-over and `/notifications` show, first, **live inbox rows** ("7 replies drafted to your Instagram comments · Review replies" → `/inbox?filter=drafted&platform=instagram`; "Comment from @user: 'nice abs'" → `/inbox/item/<id>`; "DM from @user" → `/inbox/dms`), then stored event alerts (failures, missed posts, tokens, editor posts…) as in F19. Stored `reply-ready` rows are **not listed** (they are the inbox) and are auto-acknowledged when the comment is handled (existing) or superseded. **The whole row is a link** to its target; the button is the action ("Review replies", "Approve & send", "Open in calendar"); Acknowledge stays only for informational events. Badge = number of rows shown (groups + open events), not raw alert count. Relative time ("2 days ago") on every row. Check the Inbox list supports `platform=` filtering; add it if not (list.ts, page).
- Tests: digest upsert (second hour updates, doesn't insert); groups per platform; pop-over shows a group row, not stacked digests; guarded-pages.

### B. Replies drafted on every platform (Opus)
Files: `apps/worker/src/jobs/register-engagement.ts`, `packages/engagement/src/*` (triage fallback, rules), `packages/adapters/src/comments/{index,youtube,tiktok}.ts` (+ tests), `apps/worker/src/index.ts` (source wiring only), `docs/runbooks/engagement.md`.
- **Rules-only drafting** (no AI key): instead of flagging everything, comments that pass pre-rules and look simple (short, no `?`, no negative/sensitive words from the existing rules lists, not from a promo account) get a **drafted pool reply** via the existing rotation (shadow, never sent without the creator's Approve). Questions, negativity, long comments → Needs you. Same per-person limits and rotation as AI drafts. Log line "triage: rules-only drafts (no ANTHROPIC_API_KEY)".
- **YouTube**: if `YT_CHANNEL_ID` is missing, resolve the channel with `channels.list?part=id&mine=true` (1 quota unit) at source creation using the existing OAuth refresh flow; cache it for the process. If that fails, log one line and skip YouTube.
- **TikTok via Zernio**: only if the Zernio docs research (lead sends it to you) shows official list/reply endpoints; implement `fetchRecent` (and reply) with fixtures, behind mode `tiktok: shadow` default when the source works. Otherwise keep the stub and document why.
- Tests: fake triage → simple praise drafted, question flagged; channel resolve fallback; TikTok source against fixtures if built.

### C. Touch-up that settles (Sonnet)
Files: `apps/worker/src/jobs/media-recheck.ts`, `apps/worker/src/jobs/media-fix.ts` (auto-queue only), `apps/web/lib/library/*`, `apps/web/app/library/*`, `apps/web/components/library/*`, tests.
- Recheck faster: 20 rows per tick (keep one ffmpeg at a time), and Touch-up shows "Still checking N older clips" while `qa is null or version != current` rows remain.
- **Auto-queue fixes** for fixable issues found by recheck/ingest QA (setting `touchup_autofix`, default on; originals are never modified, keeping stays a tap or Keep all).
- Unfixable issues move to a separate collapsed section "Can't be fixed automatically (N)" with Dismiss/Archive per clip; they don't count toward "needs fixing".
- Keep all result line says what's still in flight ("12 kept · 8 still fixing · 3 can't be fixed automatically").

### D. Daily Instagram (Sonnet, after A–C)
Daily job (like weekly-draft) keeps Instagram at `instagram_daily_min` (default 2) posts for tomorrow from eligible library clips, with **template captions** from a small pool per pillar in `docs/voice.md` voice (no AI), so Approve all works on the phone. Nothing auto-approves.

### E. Reel maker (Opus, after A–C)
Sounds library (upload royalty-free/own audio to R2, migration 0015 `sounds`), "Make a reel" (clip + optional trim + sound, replace or mix, 1080×1920, loudness) as a worker job like media-fix → new library media → draft post. Captions as D.

### F. Trial reels at 200 followers (later)
Alert when IG followers ≥ 200 (account-ingest data) and a Settings toggle to post IG reels as trial reels when the API accepts it.
