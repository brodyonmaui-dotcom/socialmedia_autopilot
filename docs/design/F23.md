# F23: Upload from the laptop (files or a whole folder) → Library → caption → Approve & schedule; then Studio

Status: spec, 2026-11-26. Why: finished videos (voiceovers done) sit in laptop folders (full workout log, upper/lower body sets, physique checks) and never get posted; the laptop CLI ingest is too much friction. One migration: **0017**.

## Design decisions (lead)
- **Browser upload, no laptop agent.** `<input type="file" multiple accept="video/*">`, drag-and-drop, and **Choose folder** (`<input webkitdirectory>`, works in desktop Chrome/Edge/Safari/Firefox). Phone uses the same page (file picker).
- **Through our server, chunked** (8 MiB parts → S3 multipart on R2 from the server). No R2 CORS setup, no keys in the browser, resumable per part, works behind Caddy. Raw files land under the private prefix `incoming/<uploadId>.<ext>` and are deleted after processing.
- **Location boundary**: the raw upload can carry GPS/QuickTime location; it's private and short-lived. The worker remuxes with metadata stripped (`-map_metadata -1 -map_chapters -1`, plus the existing `META` strip from packages/media/src/fix.ts), re-checks no location tags remain (as runFix does), then stores `library/<sha256>.mp4`. Only the **file's basename** is kept (`source_path`), never the folder path; the library folder label = the file's **parent directory name** (validated by `packages/core/src/folder.ts`).
- **Dedupe**: before uploading, the page asks which files are already in (same basename + size in `uploads` done/duplicate); after processing, `media.content_hash` on conflict → status `duplicate` pointing at the existing media.
- **Approve & schedule** = the creator's tap on a confirm that lists each post, platform and time. It reuses `apps/web/lib/library/add-to-calendar.ts` (drafts at next open slots, lock, caps, duplicate guard) and then the normal approve path (`planTransition` approve / `approveItemsAction` logic) for the created ids: anything with a block warning (empty caption, duplicate, lint) stays a draft and is reported. No new publish path.

## Interfaces (U1 builds, U2 consumes; exact)
Migration `0017_uploads.sql`: `uploads(id uuid pk default gen_random_uuid(), original_name text not null, size_bytes bigint not null, content_type text, folder text, r2_key text not null, s3_upload_id text, parts jsonb not null default '[]', status text not null default 'uploading' check (status in ('uploading','uploaded','processing','done','duplicate','failed','aborted')), media_id uuid references media(id), error text, created_at timestamptz not null default now(), updated_at timestamptz not null default now(), finished_at timestamptz)`; index on (status), on (original_name, size_bytes).
```ts
// apps/web/app/library/upload-actions.ts ("use server", requireSession)
export async function checkUploadsAction(files: { name: string; size: number }[]): Promise<{ name: string; size: number; already: boolean; mediaId?: string }[]>;
export async function startUploadAction(f: { name: string; size: number; type: string; relPath?: string }): Promise<{ ok: true; uploadId: string; partSize: number } | { ok: false; error: string }>;
// apps/web/app/media/upload/[id]/part/[n]/route.ts   PUT body = raw bytes of part n (1-based, ≤ partSize; all but last ≥ 5 MiB) → 200 { etag }   (requireSession)
// apps/web/app/media/upload/[id]/complete/route.ts   POST → 200 { status: "uploaded" }
// apps/web/app/media/upload/[id]/abort/route.ts      POST → 200 { status: "aborted" }
// apps/web/app/media/upload/status/route.ts          GET ?ids=a,b → 200 [{ id, status, mediaId?, posterUrl?, error? }]
```
Limits: video extensions mp4/mov/m4v (and `video/*` MIME), ≤ 2 GiB per file, ≤ 200 files per batch.
Worker job `apps/worker/src/jobs/media-ingest.ts`: like media-fix (pg-boss tick every minute, `for update skip locked`, one at a time, stale `processing` > 2 h → failed): download → strip → probe → `runQa` → poster → sha256 → upload → `insertMediaRow({ folder, source_path: basename, derivedFrom: null })` (on conflict content_hash → duplicate) → delete incoming object → `done` + `media_id`. If Touch-up auto-fix is on, `autoQueueFix` after QA (existing helper). Config alert when storage/ffmpeg missing (existing pattern).
