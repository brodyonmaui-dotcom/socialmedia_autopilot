# F19: Phone-use fixes (approvals, missed posts, notifications, mobile cleanup, bulk touch-up, IG verification)

Status: spec, 2026-11-20. From the creator's phone use. No migration. Display times use `localClock12` / `clock12FromHHMM` (`packages/core/src/time.ts`); stored values, form inputs (`<input type="time">`) and comparisons keep "HH:MM"/ISO.

## Audit (root causes)
- Card label is a worst-of roll-up over the card's platforms (`apps/web/lib/calendar/model.ts:36-55`): one draft sibling makes an approved card say "Needs approval".
- "Approve all" button counts every draft (`apps/web/app/calendar/page.tsx:77-101`); the dialog counts only approvable ones (`approveAllSummary`, `lib/calendar/plan.ts:51`). Blocked / past-time / no-time drafts are the "stay as they are".
- Inline Approve form only on Home's variant (`PostCard.tsx:135-145`); calendar uses the ⋯ menu.
- Banner's "Open week" link ignores the week being viewed (`lib/status/posting.ts:146`).
- Every time change goes through draft (`transitions.ts:184`); no series field exists. The only series signal is "Day N" in caption/title (`scripts/skills/lib/backfill.ts:80-83` `DAY_RE`, `seriesOf`).
- `missed-slot` alerts are never auto-acknowledged; `reply-ready` rows carry `comment_id` but the row has no link/action.

### S1 reschedule core (implementer, Opus): data integrity
Files: new `packages/core/src/series.ts` (+test; move `DAY_RE`/`seriesOf` here, `scripts/skills/lib/backfill.ts` re-exports), new `apps/web/lib/calendar/reschedule.ts` (+ unit and DB tests), `apps/web/app/calendar/actions.ts` (**add** `rescheduleMissedAction` only), `apps/web/lib/batches/pg-store.ts` (auto-ack only).
```ts
export interface ReschedulePlanRow { id: string; platform: Platform; from: string; to: string | null; series: { key: string; day: number } | null; title: string; reason?: "no-slot" | "not-missed" }
export async function previewRescheduleMissed(pool: Pool, itemIds: string[] | "all", now: Date, timeZone: string): Promise<ReschedulePlanRow[]>;
export async function rescheduleMissed(pool: Pool, itemIds: string[], now: Date, timeZone: string, sessionId: string | null): Promise<ReschedulePlanRow[]>;
// app/calendar/actions.ts — requireSession; FormData: itemId (repeated, uuid-validated), returnTo (relative path starting "/" only, else "/calendar"); redirects to returnTo with ?notice=rescheduled&n=<count>
export async function rescheduleMissedAction(formData: FormData): Promise<void>;
```
Rules:
- Missed = `status 'approved'`, batch approved, platform ≠ snapchat, `scheduled_for < now − 60 min` (reuse `isMissedSlot` from `lib/status/posting.ts` or the engine's `isMissed` grace, one definition). Anything else → row with `to: null, reason: "not-missed"`, untouched.
- Slot: `assignSlots` (`packages/core/src/scheduler.ts:115`) per item, single platform, `window {notBefore: now + 10 min, notAfter: now + 7 days}`, `cadence = loadCadence`, `existing` = every non-rejected scheduled item on any platform in that range (minus the items being moved) **plus each assignment already made in this call**. No slot → `reason "no-slot"`.
- Priority: series rows first (`seriesOf(title || caption)` non-null), ordered by series key then day number ascending; then evergreen by original `scheduled_for` ascending. So Day 10 gets the earliest slot and Day 11 never lands before Day 10 on the same platform.
- Write: one transaction, `pg_advisory_xact_lock(hashtext('reschedule-missed'))`, re-select the items `for update` and re-check "missed" inside the lock, re-plan there (the preview is advisory), then `update batch_items set scheduled_for = $to, approved_at = $now, updated_at = $now where id = $id and status = 'approved' and scheduled_for = $from` (0 rows → skip that item), one `batch_item_events` row `kind 'move'`, `from_status/to_status 'approved'`, detail `{"reason":"missed-reschedule","from":…,"to":…}`, and `update alerts set acknowledged_at = $now where kind = 'missed-slot' and batch_item_id = $id and acknowledged_at is null` (check the real ack columns in `queries.ts:106`). Status stays `approved`; idempotency key unchanged (the post was never sent: the guard holds it before claim). The creator's tap on a confirm that shows the new time is the approval of that time.
- `pg-store.ts` `apply`: when an item changes status or `scheduled_for`, acknowledge its open `missed-slot` alert in the same transaction (Move, Reject, Record-published resolve it).
- Tests (DB): Day 10/Day 11/evergreen ordering; caps respected with existing posts; second call is a no-op ("not-missed"); concurrent calls don't double-assign a slot; a draft or published item is untouched; alert acked; event row written.
