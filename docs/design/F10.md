## Where we start
- **Adapter** (`packages/adapters/src/snapchat.ts`):
  - `SnapchatHandoff {postId, mediaUrl, caption, checklist}`.
  - `SNAPCHAT_CHECKLIST` (Spotlight not Story; location/Snap Map off; "if blank, open Snapchat once"; one a day).
  - `snapchatCaption()` keeps the first line plus ≤ 2 hashtags, and `buildSnapchatHandoff(post: OutboxPost)`.
  - `createSnapchatAdapter().publish` always throws `NonRetryableError`, and the registry never registers it.
- **Daily pick.** `pickSnapchatDaily(posts, opts)` (`packages/analytics/src/snapchat.ts:40`) returns `SnapchatPick {clipKey, mediaId, batchItemId, platform, views, platformMedian, score, postedAt}`. It picks the best IG/TikTok performer of the last 48 h vs the platform median and never resends a clip (`alreadySent`).
- **Scheduling.** Cadence has `snapchat: {days: 2, slots: 0}` stagger and `dailyCaps.snapchat = 1` (`packages/core/src/cadence.ts:65,70`). So approved batches already contain Snapchat items with times.
- **The outbox never fires them.** `engine.ts:146-150` sees no adapter, so the item is `skipped` every tick and stays `approved` forever. Nothing on the phone shows them.
- **Status CHECK.** It allows `published` and `rejected` (`0006_auth_approval.sql:84-86`). Audit rows go to `batch_item_events` (0006).
- **Media.** The clean file URL is `PUBLIC_MEDIA_BASE + "/" + r2_key` (worker `apps/worker/src/jobs/outbox.ts:76`). `PUBLIC_MEDIA_BASE` is a **different origin** (the R2 custom domain, `.env.example:12`). The web container gets the same `.env` via `env_file`.
- **Existing evidence.** The M0 test page `/snap-test` (public static, `infra/static/snap-test.html`, Caddyfile `handle /snap-test*`) proved the flow (`docs/research.md:119-122`): Web Share from Safari → Snapchat → Spotlight works, full length, and the caption carries over. The gotcha is a blank sheet until Snapchat has been opened once. Still unverified: whether location/Snap Map is off on the posting screen.
- **Time zone.** Creator-local dates come from `TZ_CREATOR` (env only). The web already reads it in `apps/web/lib/batches/context.ts:22`. Use `localDate()` from `@autopilot/core` (`time.ts:51`).
- **Guards.** `requireSession()` and the static guard test cover `page.tsx`, `actions.ts` and `route.ts` (F7 R6 strengthened it: the first await must be `requireSession`).

## Goals
1. **`/handoff` page (phone first).** It lists Snapchat items where:
   - `bi.platform='snapchat' and bi.status='approved' and bi.approved_at is not null and b.status='approved'`, **and**
   - `localDate(scheduled_for, TZ) <= today`.

   Items due today come first. Older ones go under "Missed", with the same actions.

   Each card shows:
   - the label and duration;
   - the Snapchat caption (`snapchatCaption`) with a **Copy** button;
   - `SNAPCHAT_CHECKLIST`, with "location / Snap Map OFF" highlighted;
   - a lint state. A `lintText` privacy error **blocks** Share and shows the rule; re-checking at handoff closes the C5 gap for this route.
2. **Share, in two taps.**
   - Tap "Prepare": `fetch('/app/handoff/media/<itemId>')` → `Blob` → `File(…, 'video/mp4')`, showing the size.
   - Tap "Share": `navigator.canShare({files})` → `navigator.share({files, text: caption})`.
   - Two taps keep `share()` inside a fresh user gesture. On iOS, a long fetch between the tap and `share()` loses the gesture.
   - Fallbacks:
     - `canShare` is false → show "this browser can't share files; open on the iPhone".
     - An `AbortError` (the user closed the sheet) is not an error.
3. **Same-origin media proxy.** `apps/web/app/handoff/media/[itemId]/route.ts` (GET, `requireSession()`) does the following:
   - It streams the clean file from `PUBLIC_MEDIA_BASE/r2_key`, so no R2 CORS change is needed.
   - It serves only Snapchat items that are approved and due, and only when `r2_key` is set. Otherwise it returns 404.
   - It sends `Content-Type: video/mp4` and `Cache-Control: private, no-store`, and never sends `source_path`.
4. **"Mark posted", behind a tap-confirm sheet.**
   - It runs a conditional update `approved → published`, sets `updated_at`, and leaves `platform_post_url` null. An optional "paste Spotlight link" field accepts `https://` links on Snapchat domains only.
   - It writes a `batch_item_events` row with `kind='snap-posted'` and the session.
   - It refuses if the row changed underneath ("reload").
5. **"Skip today".**
   - It moves the item to the next creator-local day that has no other approved Snapchat item, keeping the same local time.
   - It writes an event `snap-skip` with `detail {from, to}`.
   - It respects the cap of 1 per day. It doesn't change the status. That matches the checklist line "skipped days just roll forward".
6. **"Drop"** (reject, behind a confirm) uses the existing F2 `reject` transition semantics, plus an event.
7. **Home and nav.** Home shows "Snapchat: N to share today" linking to `/handoff`. When nothing is due, the page shows `pickSnapchatDaily`'s suggestion **read-only**, with a link to `/batches` (OQ2).

## Non-goals
- Any automation of Snapchat. There is no API (Zernio is `403 PLATFORM_BETA_RESTRICTED`, `docs/research.md:113`). No browser bots.
- Spotlight analytics (Snapchat metrics stay manual; F9 non-goal).
- Creating batch items from the daily pick without approval (non-negotiable 2).
- Changing `/snap-test` or the Caddy public list.
- Push reminders for "time to share". F8 could add a kind later.

```ts
// apps/web/app/handoff/actions.ts: markPostedAction, skipAction, dropAction; each `await requireSession()` first
// apps/web/app/handoff/ui/ShareButton.tsx ("use client"): prepare → share state machine, never logs the URL
```

**Rules**
- The time zone is missing → the page shows "TZ_CREATOR not set" and lists nothing. No UTC guessing for "today", because a wrong day means a double share.
- Every write is `update … where id=$1 and platform='snapchat' and status='approved'`. If 0 rows → refuse.
- `markPosted` validates the optional URL with `new URL()`: `https:` only, and a host ending in `snapchat.com`. Anything else is dropped, not stored.
- The proxy route never forwards upstream error bodies, and it never includes `PUBLIC_MEDIA_BASE` in responses or logs.

## Data model
None new. The flow uses existing columns (`status`, `scheduled_for`, `updated_at`, `platform_post_url`) and `batch_item_events` (`kind` text: `snap-posted`, `snap-skip`, `snap-drop`). The status CHECK already allows `published` and `rejected`.

## Acceptance criteria (whole item)
1. On the iPhone: Home → "Snapchat: 1 to share" → `/handoff` → Copy caption → Prepare (size shown) → Share → Snapchat → Spotlight, with location off → back → Mark posted → confirm. The item disappears and an event is written.
2. Skip moves the item to the next free day, never two on one day. Drop rejects it. Both are audited.
3. The outbox still never fires Snapchat. The existing "Snapchat can't reach the outbox" test stays green.
4. No public exposure: the proxy is session-guarded under `/app`, R2 CORS and Caddy are unchanged, and no place, time zone or domain appears in code or docs.
5. `pnpm typecheck`, `pnpm test` and `pnpm simulate-week` are green.

## Open questions (recommended default in **bold**)
1. **Should "Mark posted" need a tap-confirm?** **Yes.** It's a one-way status change that the analytics and the daily pick (`alreadySent`) rely on.
2. **What happens when nothing is due?** **Show the `pickSnapchatDaily` suggestion read-only, with a link to `/batches`.** Turning it into a post goes through a draft + approval (non-negotiable 2). Auto-adding the pick to the batch would need a web "add snapchat item" path, which `PgBatchStore.addItem` already supports (F2). Do that in a later item if the creator wants it.
3. **Same-origin proxy or R2 CORS?** **Proxy.** It needs no bucket change (that would be a "connecting/settings" ask), it's session-guarded, and the files are short clips. Revisit only if streaming through the web container is too slow on the VPS.
4. **Must Mark posted ask for the Spotlight link?** **No, it's optional.** Spotlight URLs aren't needed for anything yet.
5. **"Location / Snap Map off" is still unverified** (`docs/research.md:122`). **Keep it as the first checklist line and ask the creator to confirm it on the first real share**, then log it in research.md. The first real post per platform needs the creator's explicit OK anyway (non-negotiable 2).
