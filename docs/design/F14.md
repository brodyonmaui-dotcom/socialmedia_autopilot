# F14: Weekly loop (Sunday top-up draft, Monday report alert, captions via the skill)

Status: **final spec, 2026-11-19** (rewritten after run 4: Calendar replaced Batches, the editor pipeline writes into the same per-week batch). Creator decisions in chat 2026-11-19: Sunday 18:00 / Monday 08:00 creator-local; top up to **1 library clip per uncovered day**; each clip goes to **Instagram, YouTube, TikTok** (no Snapchat). No migration.

## Goals
1. **Sunday job `weekly-draft`** (18:00 in `TZ_CREATOR`): for next week (the Monday after the run), find the days with no post yet and add one library clip per such day, as `draft` items for IG + YT + TikTok, slotted by `assignSlots`, **captions and titles empty**. Raise one pushed `batch-ready` alert. Idempotent and safe next to the editor pipeline.
2. **Monday job `weekly-report`** (08:00 in `TZ_CREATOR`): if anything was published in the finished week, raise one page-only `report-ready` alert linking to `/analytics?days=7`. No LLM, no storage.
3. **Captions stay a Claude Code skill** (docs/decisions.md §4): `pnpm skill:weekly-batch pending` lists draft items with empty text; `pnpm skill:weekly-batch fill <file> [--write]` lints and writes captions/titles.
4. **UI**: Home shows "Next week: N posts need captions" when that is true; `/alerts` labels both kinds.
5. **Nothing is approved by the job.** Empty captions already block approval (`apps/web/lib/batches/warnings.ts:80`, `caption.missing`, severity block); auto-approve only takes `origin = 'editor'` (`apps/web/lib/editor/auto-approve.ts:39`); `listDue` needs `approved_at` and an approved batch (`apps/worker/src/jobs/outbox.ts:132`).

## Rules (both tasks must follow)
- **Batch row**: same as `tools/ingest-agent/src/ready/write.ts:120-158`: one transaction; `pg_advisory_xact_lock(hashtext('batch-week:' || weekStart))`; reuse the newest non-archived batch for `week_start`, else insert `'draft'`. Batch status is left alone (adding draft items can't change the derived status; see the comment above `writeReadyItems`). Sharing that lock is what keeps the job and the editor pipeline from racing.
- **Items**: `status 'draft'`, `origin 'weekly'`, `caption ''`, `title ''` for YouTube and `null` for the rest (match how the editor writes titles), `trial null`, `ingest_key = 'weekly:<weekStart>:<mediaId>:<platform>'`, `insert ... on conflict (ingest_key) where ingest_key is not null do nothing`. Plus one `batch_item_events` row `kind 'add'`, detail `{"origin":"weekly"}`.
- **Week**: `weekStart` = the Monday (local date in `TZ_CREATOR`) after `now`. Reuse whatever helper the editor pipeline / calendar uses for week starts; don't write a new one if one exists.
- **Covered day**: a local day of that week that already has ≥1 `batch_items` row with `status <> 'rejected'` and `scheduled_for` on that day (any platform, any origin). Uncovered days get one clip each, `window` = that local day, `platforms [instagram, youtube, tiktok]`, `sameDay: true`. Pass all non-rejected scheduled items of the week as `existing` so daily caps hold. Cadence comes from the same settings loader `scripts/schedule-batch.ts` uses (move it into a package if the worker can't import it; keep the script working). Items `assignSlots` can't place are dropped and counted in the log line.
- **`pickClips(rows, { count, recentlyUsed })`, pure**: eligible = the same "ready / visible" predicate the library uses (`packages/media/src/library.ts`: not archived, has a clean `r2_key`, not an original superseded by a kept fix; check 0014 semantics there), and not in `recentlyUsed`. `recentlyUsed` = media with a non-rejected `batch_items` row whose `scheduled_for` is ≥ now − 28 days (future included). Order: newest first (`captured_at` desc, then `created_at` desc, then `id`), then round-robin across pillars (pillar order = first appearance in that list). Deterministic.
- **Alerts** use the not-exists pattern of `analytics-ingest.ts` (`insert ... select ... where not exists (select 1 from alerts where kind = $k and message = $m)`), so a re-run raises nothing. Messages hold counts and the week date only: no clip names, paths, captions, ids or places. Examples: `Next week (from 2026-11-23): 5 clips added, 15 posts need captions`; `Last week's report is ready: 18 posts published`.
- **Cron**: `WEEKLY_DRAFT_CRON = "0 18 * * 0"`, `WEEKLY_REPORT_CRON = "0 8 * * 1"`, registered with pg-boss `schedule(name, cron, data, { tz: TZ_CREATOR })` (verify the option in the installed pg-boss 10.4.x typings). No `TZ_CREATOR`: log one line and don't schedule. Never commit a zone; tests use `America/New_York` as an arbitrary fixture zone (that's in existing tests already; check).
- Dry-run doesn't matter (private draft + alert only), like `analytics-ingest`.
