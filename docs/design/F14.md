# F14: Weekly loop in the worker (Sunday draft batch, Monday report, "Up next" UI)

Status: draft (Fable run 3 wrap-up, 2026-11-14). Fable gates it; Opus implementers build. Line numbers are for branch `fable/run-3-2026-11-14`; re-grep before citing. **Probably no migration** (OQ3).

## Where we start
- **The weekly loop is manual.** `scripts/skills/weekly-batch.ts` checks a draft file (`check`), writes a review (`review`) and, only with `create`, calls `createDraftBatch` (`scripts/skills/lib/batch-draft.ts:116`), which inserts one `batches` row and its `batch_items` as `draft`. It never approves. `scripts/schedule-batch.ts` assigns `scheduledFor` from the cadence grid (caps, stagger, DST-safe in `TZ_CREATOR`); it is a script, not an importable module. `weekly-report` is a skill over `post_metrics`.
- **Worker jobs.** `apps/worker/src/queue.ts` lists nine queues; none is weekly. Registration pattern: `register-outbox.ts` (`boss.createQueue`, `boss.work`, `boss.schedule(name, cron)`); the cron-only pattern with an alert is `analytics-ingest.ts` (`ANALYTICS_INGEST_CRON`, `raiseMetricsHealthAlert` at `:96`: `insert ... select ... where not exists (... unacknowledged ...) returning id`).
- **The AI split (docs/decisions.md section 4) decides T1.** The server runs only Claude Haiku 5.5 for comment/DM triage and reply drafts, with a $5 hard spend limit. "`weekly-batch` (captions, titles, schedule), `research-brief`, `weekly-report`, `platform-check`" are **Claude Code skills on the creator's plan, run when he opens a session**. So a worker job must **not** call an LLM to write captions. It assembles clips and slots and leaves captions empty, flagged. (Spend on the Anthropic key is a budget-affecting setting; adding a caption call to the worker needs the creator's explicit OK, non-negotiable 6.)
- **Empty captions are legal in the DB** (`batch_items.caption text not null default ''`, `0001_init.sql:36`) but `checkDraft` rejects them (rule `caption.empty`, `scripts/skills/lib/batch-draft.ts:77`), so `createDraftBatch` can't be reused as-is (OQ1). The batches UI already blocks approval on lint and placeholders (`apps/web/lib/batches/warnings.ts:73`); whether an empty caption blocks is OQ2.
- **Alerts.** `ALERT_KINDS` (`packages/core/src/types.ts:78-83`) has no weekly kinds; `PUSH_KINDS_DEFAULT` (`:97`) lists five pushed kinds. `alerts.platform` holds an `AlertSource` (`:94`; `"all"` is used for whole-system rows like the `config` alert, `outbox.ts:261`). Alerts UI, push job and the `alert_push` setting are documented in `docs/runbooks/alerts-push.md`.
- **Report.** `apps/web/app/analytics/page.tsx:64` computes `buildWeeklyReport(posts, { weekStart, timeZone, now })` live from `loadPostRecords`; nothing is stored. So "stored where /analytics reads it" needs no storage (OQ4).
- **Home / batches.** Home's "Up next" lists approved posts still ahead (`apps/web/app/page.tsx:67`, `upNext*` helpers under `apps/web/lib/home`); the nav badges come from `AppFrame` (`apps/web/components/AppFrame.tsx`). Both were restyled in F12 (6bcaa91 and earlier); use the v2 components in `apps/web/components/ui`.

## Goals
1. **Sunday draft job** (`weekly-draft`): creates next week's batch as a `draft`, from the library, with clips and time slots filled and **captions empty**, then raises a `batch-ready` alert (pushed, so the phone tells him a batch waits). Idempotent per `week_start`: a second run, or a re-run after a crash, creates nothing.
2. **Monday report job** (`weekly-report`): raises a `report-ready` alert (page-only) linking to `/analytics` for the finished week. No LLM, no new storage.
3. **UI**: Home "Up next" shows the draft batch waiting for review (week, post count, "Captions needed" when empty); the `/batches` nav badge counts drafts waiting.
4. **Nothing is approved by the job.** Only the creator's tap approves (non-negotiable 2); the worker gate (`listDue`) still requires `approved_at` and an approved batch, so a job-made draft can never publish.

## Non-goals
- Writing captions or titles in the worker (AI split). The skill fills them in a session: `pnpm skill:weekly-batch` reads the waiting draft batch (T1 adds the hook).
- Approving, scheduling for real, or editing an existing batch.
- Choosing content with an LLM, or research-driven picks (M5).
- A cron the creator can edit in the UI (cron constants in code, like `ANALYTICS_INGEST_CRON`).
- Pushing `report-ready` (page-only by decision in the outline).

**Rules**
- Slot assignment comes from a shared pure function extracted from `scripts/schedule-batch.ts` (T1 step 1), so the script and the job can't drift. The job passes `batch_items.scheduled_for` from the cadence grid and existing commitments, like the script does.
- The job inserts one batch + items in one transaction, `status = 'draft'`, `approved_at` null, `trial` null (no TikTok draft flags: those are his call). It checks `select 1 from batches where week_start = $1` first and relies on a unique guard (OQ3).
- Archived media and media with no clean file (`r2_key` null) are never picked (as `createDraftBatch` and A11 do).
- Alert text is generic ("Next week's batch is ready for review: 18 posts, captions needed"). No clip names, paths or places in alerts or push (location boundary; push travels through Apple).
- Missing `TZ_CREATOR` or an empty library: log one line, create nothing, raise nothing.
- Dry-run does not matter: the job writes only a draft and an alert (private to him), like `alert-push` and `analytics-ingest`.

## Acceptance criteria (whole item)
1. On a scratch DB, running the Sunday job twice leaves exactly one draft batch and one `batch-ready` alert; nothing in it can publish before approval (`listDue` test).
2. The Monday job raises one page-only `report-ready` and stores nothing new.
3. Home and the `/batches` badge show the waiting draft; approving it still goes through the normal F2 confirm flow.
4. No LLM or platform call exists in either job; no secret, path or place appears in an alert, log line or push.
5. `pnpm typecheck`, `pnpm test`, `pnpm simulate-week` green; default stays dry-run.

## Open questions (recommended default in **bold**)
Lead review 2026-11-14: every bold default is approved; OQ3 was changed to the advisory lock (no 0009). OQ5 and OQ6 still need the creator's word in chat before T1.

1. **How does the job insert items with empty captions when `createDraftBatch` refuses them?** **Add an option to `createDraftBatch` (`allowEmptyCaption: true`, default false) rather than a second insert path**, so the media/archived checks and the transaction stay in one place. The job uses a worker-side import of the same function (it lives under `scripts/skills/lib`; if the worker can't import `scripts/`, move it to a package in T1 and keep the script re-exporting).
2. **Does an empty caption block approval in the UI?** Not confirmed from `warnings.ts` alone. **Make it a `block` warning ("caption needed") if it isn't already**, so a captionless draft can't be approved by accident; T3 adds the test.
3. **Idempotency: code check or a unique constraint on `batches(week_start)`?** **Lead decision (2026-11-14): no migration. The job takes `pg_advisory_xact_lock(hashtext(week_start))` and checks for an existing batch for that week inside the same transaction; a second run finds it and exits. The dev DB already holds duplicate `2099-01-05` test weeks, so a unique index would fail there and buy nothing the lock does not.**
4. **Is the report stored?** `/analytics` computes it live. **No storage; the alert links to `/analytics?week=...`.** If a stored copy is wanted later, use a `settings` key, not a table.
5. **When do the jobs run?** **Sunday 18:00 and Monday 08:00 creator-local** (the decision is the creator's; times are a guess). pg-boss cron needs the creator time zone: check that the installed version's `schedule` accepts a `tz` option and pass `TZ_CREATOR`; otherwise compute UTC from it at registration and handle DST by running hourly and gating on local time. Never commit the zone.
6. **Which clips?** **Newest ready media not used in the last 4 weeks, up to `slotsPerDay x 7 / platforms`, round-robin over pillars**; he swaps clips on the phone. The rule is a guess at his taste: confirm in chat before T1, and keep it in `pickClips` so it is one function to change.
7. **Should `batch-ready` push on a Sunday evening?** **Yes (outline).** It is the one weekly push; the creator can remove it with the `alert_push` setting.
