## Facts this design relies on (`docs/research.md`, `docs/runbooks/token-renewal.md`)
- **IG comments: polling first.**
  - Webhooks need a Live app plus Advanced Access. Our app is in **Development mode** (verification log #2, M0 Meta setup).
  - **One `/media?fields=…,comments{…}` call returns recent posts + comments** (M0 IG result).
  - Reply, hide, delete and toggle on own media are documented at Standard Access.
  - Exact endpoints and params for reply and hide **must be re-read on Meta's docs at build time** (non-negotiable 7). They are not in the verification log yet.
- **IG DMs**
  - Answers only within **24 h of the user's last message**; the app can never open a thread. The Human Agent 7-day tag needs review: not available.
  - Past 24 h, a draft becomes "copy + open Instagram" (verification log #3).
  - voice.md: **he sends DMs himself**. So F3 drafts only and never sends DMs.
- **YouTube**
  - Listing threads costs 1 unit. `comments.insert` and moderation cost 50 units each, from a 10,000/day pool.
  - Whether our refresh token has the `youtube.force-ssl` scope is **unknown** (OQ2).
- **TikTok via Zernio**
  - Comments arrive by **webhook**. Comment management needs no Business account.
  - **But the creator chose free plan only: "TikTok metrics and comment replies are manual"** (token-renewal.md:25).
  - So TikTok is **out of automation** in F3. There is only an interface stub, disabled.
- **AI**
  - Claude Haiku 5.5 with structured output, buckets `simple_positive | negative | hide_flag | flag` (scripts/probes/anthropic.ts:14).
  - **A refusal or low confidence = flag** (decisions §4). The M0 probe sorted 6/6 correctly, including "where is this trail?" → flag.
  - There is a $5/mo hard limit on the key.
- **voice.md rules for replies**
  - Positive: 2–6 words, always varied, "never the same reply twice in a row, and never twice to the same person in a week".
  - Mockery: overly positive only, rotated.
  - Threats, slurs, doxxing and scams: hide where possible, no reply, flag.
  - Questions, brand inquiries, location/schedule and anything uncertain: no reply, flag.
  - No swearing in replies or DMs (`lintText` kind `reply`/`dm` already enforces this, voice-lint.ts:22).

## Goals
1. **Ingest**
   - Poll IG comments every 5 min: one call over recent media, nested comments and replies.
   - Poll YouTube every 15 min with read-only `commentThreads.list`.
   - Store new comments idempotently.
2. **Triage** each new comment through a `TriageClient` (Haiku in prod, a deterministic fake in tests) plus **hard rules that run before and after the model**:
   - Before: any comment with a question mark, a link, a location/schedule word, or that mentions brand/collab/business → `flag`, without calling the model.
   - After: the draft must pass `lintText(kind:"reply")`, be 2–8 words, and contain no place. Any failure → `flag`.
3. **Plan actions**
   - `reply` for `simple_positive`/`negative` → text picked by **rotation** (below).
   - `hide` for `hide_flag` → on IG only, only when hiding is enabled.
   - `flag` → inbox.
   - **Never delete.**
4. **Shadow mode is the default** per platform. Everything is computed and stored, and the inbox shows "would reply: …". Nothing is sent or hidden.
5. **Live sending** happens only when all of these hold:
   - `DRY_RUN=false`
   - `settings.engagement.mode[platform] = "live"`
   - the kill switch is off
   - limits allow it
   - the action is ≥ `minDelayMin` old (the veto window)

   Switching a platform to live is an auto-reply behaviour change, so it needs **the creator's explicit OK in chat** (non-negotiable 2). The UI shows that warning and the action records an audit event.
6. **Limits**
   - At most 1 auto-reply per person per 7 days per platform.
   - Per-platform hourly and daily caps; a global daily cap.
   - Skip the thread when the creator already replied in it (human-takeover pause).
7. **Kill switch**: a settings flag plus `ENGAGEMENT_KILL=1` in env.
   - Checked immediately before every send.
   - Trips automatically on: 3 consecutive send failures; any error that looks like an action block, spam flag or rate limit; or AI spend errors.
   - Tripping raises an alert.
8. **Double-reply safety, same discipline as the outbox**
   - One `engagement_actions` row per (comment, kind).
   - Re-fetch the thread before a retry, and skip it if our reply already exists.
   - A timeout → `unknown` with no retry.
   - Bounded backoff; alert on final failure.
9. **Inbox UI** (`/app/inbox`), phone first:
   - Tabs: Flagged · Would reply (shadow) · Sent · DMs.
   - Per comment: text, post thumbnail label, bucket, draft.
   - Buttons: "Copy", "Mark done", "Send this reply" (manual send; same live gates except the mode check), "Never auto-reply to this person".
   - Big kill-switch toggle.
10. **IG DM drafts**
    - Poll IG conversations (if the read endpoint is verified, OQ3) and draft replies in voice.
    - Show a **countdown to `last_inbound_at + 24 h`**. After it passes, the label reads "window closed: copy + open Instagram".
    - Never send.

## Non-goals
- TikTok comment automation (free plan; creator's call). Webhooks of any kind (Development mode). Liking comments.
- Comment-to-DM funnels. Sending DMs. Deleting comments. Replying to comments on other creators' media.
- Snapchat (no comment API). Analytics of engagement (F5 owns metrics).

## Reply rotation (deterministic, testable)
- **Pools**
  - Seed pools in `packages/engagement/src/pools.ts`, taken from voice.md examples: `positive` (≥12 lines) and `negative` (≥8 lines).
  - The pools are stored in `settings.engagement.pools` once, and the creator can edit them later.
- **Picking a reply**
  - Candidates are the model's draft (if it passes post-rules) plus the pool.
  - Exclude: the last 3 replies sent on that platform; any text sent to this author in the last 30 days; and any text used more than 2× in the last 24 h.
  - Pick using a seeded RNG `(commentId)`, so tests are stable.
  - If nothing is left → `flag` ("rotation exhausted").
- Emoji count ≤ 1, except the mockery set that voice.md allows ("😊👍").

## Interfaces (`packages/engagement`, new package `@autopilot/engagement`)
```ts
export type Bucket = "simple_positive" | "negative" | "hide_flag" | "flag";
export type EngagementPlatform = "instagram" | "youtube" | "tiktok";
export type Mode = "off" | "shadow" | "live";

export interface InboundComment {
  platform: EngagementPlatform; platformCommentId: string; platformMediaId: string; parentId?: string;
  authorId: string; authorHandle?: string; text: string; createdAt: string; isOwn: boolean;
  /** our replies already in this thread (for existence checks and the human-takeover pause) */
  ownRepliesInThread: Array<{ platformCommentId: string; text: string; createdAt: string }>;
}
export interface CommentSource {
  platform: EngagementPlatform;
  fetchRecent(cursor: unknown, opts?: { signal?: AbortSignal }): Promise<{ comments: InboundComment[]; cursor: unknown }>;
  fetchThread(platformCommentId: string, opts?: { signal?: AbortSignal }): Promise<InboundComment | null>; // re-check before retry
  reply?(platformCommentId: string, text: string, opts: { signal?: AbortSignal; idempotencyKey: string }): Promise<{ platformReplyId: string }>;
  hide?(platformCommentId: string, opts?: { signal?: AbortSignal }): Promise<void>;
}
export interface TriageResult { bucket: Bucket; reply: string | null; confidence: number; reasons: string[]; model: string; refused?: boolean }
export interface TriageClient { triage(c: InboundComment, ctx: { postCaption?: string; pillar?: string }): Promise<TriageResult> }
export function createAnthropicTriageClient(cfg: { apiKey: string; model: string; fetch?: typeof fetch; maxTokens?: number }): TriageClient; // structured output; refusal → flag
export function createFakeTriageClient(rules?: Array<[RegExp, Bucket, string | null]>): TriageClient;

export function preRules(c: InboundComment): { bucket: "flag" | "hide_flag"; reason: string } | null;      // ?, links, place/schedule words, brand terms, blocklist
export function postRules(r: TriageResult, c: InboundComment, blocklist: string[]): TriageResult;          // lintText(kind:"reply"), length, confidence < 0.7 → flag

export interface EngagementSettings {
  mode: Record<EngagementPlatform, Mode>;            // default { instagram: "shadow", youtube: "shadow", tiktok: "off" }
  killed: boolean; killedReason?: string;
  hideEnabled: Record<EngagementPlatform, boolean>;  // default false everywhere (hide also needs live)
  limits: { perPersonDays: number; perPlatformPerHour: number; perPlatformPerDay: number; globalPerDay: number }; // 7, 10, 40, 80
  minDelayMin: number;                               // 10: the veto window
  pollMinutes: { instagram: number; youtube: number }; // 5, 15
  pools: { positive: string[]; negative: string[] };
}
export const DEFAULT_ENGAGEMENT: EngagementSettings;

export interface ActionHistory { /* queries the planner needs, backed by engagement_actions */
  lastRepliesOn(platform: EngagementPlatform, n: number): Promise<string[]>;
  repliesToAuthorSince(platform: EngagementPlatform, authorId: string, since: Date): Promise<string[]>;
  countSent(platform: EngagementPlatform | "all", since: Date): Promise<number>;
  textUseCount(platform: EngagementPlatform, text: string, since: Date): Promise<number>;
}
export type PlannedAction =
  | { kind: "reply"; text: string; notBefore: string } | { kind: "hide"; notBefore: string }
  | { kind: "flag"; reason: string } | { kind: "none"; reason: string };
export function pickReply(candidates: string[], history: { recent: string[]; toAuthor: string[]; overused: Set<string> }, seed: string): string | null;
export async function planActions(c: InboundComment, t: TriageResult, s: EngagementSettings, h: ActionHistory, now: Date): Promise<PlannedAction[]>;

export type SendGate = { ok: true } | { ok: false; reason: "dry-run" | "mode" | "killed" | "limit" | "too-early" | "human-replied" | "already-exists" };
export function sendGate(a: EngagementActionRow, s: EngagementSettings, env: { dryRun: boolean; killEnv: boolean }, counts: LimitCounts, now: Date): SendGate;
export async function runSendTick(store: EngagementStore, sources: Map<EngagementPlatform, CommentSource>, cfg: { settings: EngagementSettings; dryRun: boolean; killEnv: boolean; policy: RetryPolicy; alerts: AlertSink; now?: () => Date }): Promise<SendTickResult>;
export function shouldTripKill(recent: Array<{ ok: boolean; error?: string }>): string | null; // 3 consecutive fails, /action.?block|spam|rate.?limit|too many/i

// DMs
export interface DmThreadView { id: string; handle?: string; lastInboundAt: string; windowEndsAt: string; windowOpen: boolean; messages: Array<{ dir: "in" | "out"; text: string; at: string }>; draft?: string }
export function dmWindow(lastInboundAt: string, now: Date): { endsAt: string; msLeft: number; open: boolean };
export interface DmSource { fetchThreads(cursor: unknown): Promise<{ threads: Array<{ platformThreadId: string; participantId: string; handle?: string; messages: Array<{ id: string; dir: "in" | "out"; text: string; at: string }> }>; cursor: unknown }> }
```
- `RetryPolicy` and the timeout classification are reused from `@autopilot/core` outbox policy.
- `classifyFailure` treats a timeout as `unknown`.
- `AlertKind` gains `engagement-kill`, `engagement-failure` and `engagement-unknown`, in both core and db types.

Platform sources live in `packages/adapters/src/comments/{instagram,youtube,tiktok}.ts`. They reuse `getJson`, `redactToken`, `FetchLike` and fixtures. `tiktok.ts` is an interface stub that throws "disabled: free plan".

## Data model: `packages/db/migrations/0007_engagement.sql`
```sql
create table comments (
  id uuid primary key default gen_random_uuid(), platform text not null, platform_comment_id text not null,
  platform_media_id text not null, batch_item_id uuid references batch_items(id) on delete set null,
  parent_platform_id text, author_id text not null, author_handle text, text text not null,
  is_own boolean not null default false, commented_at timestamptz not null, fetched_at timestamptz not null default now(),
  unique (platform, platform_comment_id));
create index comments_untriaged_idx on comments (fetched_at) where not is_own;
create table comment_triage (
  comment_id uuid primary key references comments(id) on delete cascade, bucket text not null
  check (bucket in ('simple_positive','negative','hide_flag','flag')), confidence numeric, draft_reply text,
  reasons text[], model text, refused boolean not null default false, decided_at timestamptz not null default now(),
  handled_at timestamptz);                                  -- creator marked done in inbox
create table engagement_actions (
  id uuid primary key default gen_random_uuid(), comment_id uuid not null references comments(id) on delete cascade,
  kind text not null check (kind in ('reply','hide')), text text, idempotency_key uuid not null unique default gen_random_uuid(),
  status text not null default 'planned' check (status in ('planned','sending','sent','failed','unknown','cancelled','shadow')),
  not_before timestamptz not null, attempts int not null default 0, next_attempt_at timestamptz, last_error text,
  platform_action_id text, origin text not null default 'auto' check (origin in ('auto','manual')),
  created_at timestamptz not null default now(), updated_at timestamptz not null default now(), sent_at timestamptz,
  unique (comment_id, kind));                               -- one reply and one hide per comment, ever
create index engagement_due_idx on engagement_actions (status, not_before);
create table engagement_cursors (platform text primary key, cursor jsonb, polled_at timestamptz);
create table engagement_blocklist (platform text not null, author_id text not null, created_at timestamptz not null default now(),
  primary key (platform, author_id));                        -- "never auto-reply to this person"
create table dm_threads (id uuid primary key default gen_random_uuid(), platform text not null default 'instagram',
  platform_thread_id text not null unique, participant_id text not null, participant_handle text,
  last_inbound_at timestamptz, last_outbound_at timestamptz, handled_at timestamptz);
create table dm_messages (id uuid primary key default gen_random_uuid(), thread_id uuid not null references dm_threads(id) on delete cascade,
  platform_message_id text not null unique, direction text not null check (direction in ('in','out')), text text, sent_at timestamptz not null);
create table dm_drafts (id uuid primary key default gen_random_uuid(), thread_id uuid not null references dm_threads(id) on delete cascade,
  for_message_id uuid references dm_messages(id), text text not null, bucket text, created_at timestamptz not null default now(),
  status text not null default 'draft' check (status in ('draft','copied','dismissed')));
insert into settings (key, value) values ('engagement', '{}') on conflict (key) do nothing; -- merged over DEFAULT_ENGAGEMENT
```
- Shadow-mode actions are stored with `status='shadow'`. They are what the "Would reply" tab shows, and they are never sent.
- Flipping a platform to live does **not** promote old shadow rows. Only comments planned after the switch are eligible.

## Worker jobs (`apps/worker/src/jobs/`)
| Queue | Cron | Does |
|---|---|---|
| `engagement-poll` | `*/5 * * * *` | for each platform with mode ≠ off and creds, if due by `pollMinutes`: `fetchRecent` → upsert `comments` → cursor |

| `engagement-send` | `* * * * *` | `runSendTick`: due `planned` rows → `sendGate` → claim (`planned→sending`, conditional) → if `attempts>0`, `fetchThread` existence check first → `reply`/`hide` → `sent` / backoff / `failed` / `unknown` + alert; `shouldTripKill` |

With no `ANTHROPIC_API_KEY`, triage uses only `preRules` and everything else goes to `flag`. The worker logs one line at start.

## Acceptance criteria (whole item)
1. With defaults (shadow), a poll of the fixture IG and YT comments results in triage rows, "would reply" entries in the inbox and zero outbound calls. Proven by a fake fetch that fails the test on any POST.
2. Live sending needs `DRY_RUN=false` + mode `live` + kill off + limits + delay. Each gate has its own failing test.
3. Rotation and per-person rules from voice.md hold over a 1,000-comment property test. Location/schedule questions and brand inquiries are never auto-replied.
4. No double reply: unique `(comment_id, kind)`, conditional claim, existence check before retry, timeout → unknown.
5. The kill switch stops sending within one tick, and the auto-trip works.
6. DM drafts show a correct 24 h countdown, and there is no code path that sends a DM.
7. `pnpm typecheck`, `pnpm test`, `pnpm simulate-week` and `pnpm simulate-engagement` are green. The runbook says that going live per platform needs the creator's OK in chat.

## Open questions (recommended default in **bold**)
1. "Never twice to the same person in a week": does it mean the same text, or any reply? → **Any auto-reply: max 1 per person per 7 days** (stricter). Text reuse to that person is also barred for 30 days.
2. YouTube reply scope: does our refresh token include `youtube.force-ssl`? → **Assume no. Ship YT in shadow + read-only. Adding the scope needs a re-consent session with the creator** (alongside `yt-analytics.readonly`, token-renewal.md:22).
3. IG DM read endpoint at Standard Access in Development mode is unverified → **`dm-poll` is disabled by default.** A read-only probe (`probe:ig --dms`, a day task with the creator) flips `DM_POLL_VERIFIED`.
4. Do comment `username`/`from` come back for non-role users in Development mode? → **Unknown. If missing, per-person limits key on the comment's `from.id` when present, else treat every such comment as a new author but cap hard via the per-platform limits.** Verify with a read-only probe.
5. Auto-hide on IG for `hide_flag`? → **Off by default (`hideEnabled=false`). It flags only, and the creator hides with one tap in the inbox.**
6. TikTok comments? → **Out (free plan; replies manual).** The adapter stub keeps the slot open.
7. Default caps? → **10/h and 40/day per platform, 80/day global, 10 min veto delay.** YT at 50 units/reply → 40/day = 2,000 units, well inside 10,000.
