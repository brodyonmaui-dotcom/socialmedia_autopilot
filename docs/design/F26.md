# F26: No duplicate videos, a pre-publish judge, unique captions, play-before-approve, drag-trim

Status: spec, 2026-11-28. Creator: duplicates keep being attempted on Instagram (fear of losing non-follower reach); captions are a few repeated templates with the same hashtags; wants to watch the video when approving; Studio trim should be drag handles like Edits. Decisions: captions = **both** (bigger template bank always, AI when `ANTHROPIC_API_KEY` is set, $5/month cap); judge covers **Instagram, TikTok, YouTube Shorts**. One migration: **0018**.

## Platform facts (research 2026-11-28, official unless [INF]; D1 copies these into docs/research.md's verification log)
- IG: identical content → only the original is recommended; accounts that mostly post unoriginal content lose recommendations (rolling 30 days, 2026-04-30); trial reels get limited reach if the content was shared before; ≤5 hashtags (hard). Self-reposts: no explicit rule [INF: treat as duplicate].
- TikTok: unoriginal/re-uploaded content without new edits and other apps' watermarks are FYF-ineligible. Hashtag count/frequency: nothing official.
- YouTube: ≤3 hashtags shown, >60 = all ignored; unrelated hashtags and repetitive description sentences are prohibited; "inauthentic" = interchangeable, template-like videos.

## A. Duplicate guard v2 (implementer, Opus) — owns migration 0018, packages/core/src/duplicate-clip.ts, packages/db/src/duplicate-clip.ts, apps/web/lib/batches/warnings.ts (duplicate section only), apps/web/app/calendar/actions.ts (already-posted only), worker outbox pre-publish check, fingerprint step in ingest/fix/reel/studio jobs + a backfill tick
- **Same video** = any of: (1) same **lineage root** (follow `media.derived_from` to the root; touch-up fixes, reel-maker and Studio outputs share their source's root); (2) same **fingerprint**: migration 0018 adds `media.fingerprint` (text, 8 frame dHashes 64-bit hex at 10/20/…/80% + duration) computed with ffmpeg (8×9 grey frames) wherever media rows are created, plus a worker backfill tick (20 rows/tick, one ffmpeg at a time) for existing rows; match = duration within 1.0 s and ≥ 6 of 8 frames within Hamming ≤ 10 (pure function in core, tested); (3) same basename `source_path` and duration within 0.5 s.
- **Already posted counts**: items rejected with reason `already-posted` count as published at their scheduled time; IG `account_posts` rows with `batch_item_id` null are linked to media by fingerprint where the Graph API gives the reel's `media_url` (own media, official API; optional stretch — skip if it needs new scopes; say so).
- **Rule** (same platform): same video scheduled/published within **90 days → block** ("This video was already posted on Instagram on Fri Nov 20 · open it"); older → warn. Derived Studio/reel output with ≥ 3 s of new edits (text overlay or different trim/sound) of a posted clip → **warn** only ("Uses footage you posted on …"), except Instagram where it stays a warn and is flagged for trial reels (IG: trials need new content).
- Enforced at: every picker (daily-instagram, weekly-draft, media-reel, add-to-calendar, approve-and-schedule, scripts/skills batch-draft) via one db helper `recentVideoUse(db, { mediaId, platform, now })`; the calendar warning (block = can't approve); and **in the outbox right before publishing** (create container / upload / Zernio call): a block holds the item (status unchanged, alert kind `duplicate-held`, added to ALERT_KIND/describeAlert/push defaults) — never publish it. Tests for each path incl. a fixed copy, a re-upload with a new hash, and an already-posted reject.

## B. Judge + captions (implementer, Sonnet) — owns packages/core/src/{judge.ts,hashtags.ts,caption-templates.ts,caption-compose.ts}, packages/research/src/auto/* only for a shared Anthropic call helper if useful, the caption calls in apps/worker/src/jobs/{daily-instagram,weekly-draft}.ts and apps/web/lib/library/ready-to-post.ts, docs/voice.md (read), docs/research.md log
- **Hashtag bank** (`hashtags.ts`): niche sets per group (gym/hypertrophy, college fitness, running, meal prep, physique, lifestyle/discipline) + a few broad tags; `pickHashtags(group, platform, seed, recentSets)` → IG 3–5, TikTok 3–5, YouTube 2–3 (+ `#shorts`), never the same set as any of the last 5 posts on that platform. Hashtags live in the caption tail as today.
- **Template bank**: hooks × bodies × CTAs per group (≥ 25 hooks, ≥ 20 bodies, ≥ 10 CTAs per group, voice.md voice, no claims about specific workouts unless the clip's folder/name says it, e.g. "upper body") composed deterministically; avoid any caption with similarity ≥ 0.6 (word-trigram Jaccard) to the platform's last 30 days. Clip context: folder + basename ("Upper body sets", "physique check") picks the group and body lines.
- **AI captions** (when `ANTHROPIC_API_KEY` is set): `composeCaption({ group, platform, clipContext, recentCaptions })` calls Claude (model `claude-haiku-5-5`, max_tokens ≈ 300, prompt from docs/voice.md + rules: platform hashtag limits, no places/whereabouts, unique vs the recent list), validated by the judge; on error/over-budget → template. Monthly spend tracked in `settings` (`ai_caption_spend_<YYYY-MM>` in cents from usage tokens); stop at 500 cents. Log one line per call, never the key. Read the claude-api skill / existing `hook-line.ts` for the call pattern.
- **Judge** (`judge.ts`, pure): `judgePost({ platform, caption, title?, durationS, recent: { captions: string[]; hashtagSets: string[][] }, duplicate?: { level, message } })` → `{ score 0–100, checks: [{ id, level: "pass"|"warn"|"block", message, fix? }] }`. Checks: hashtag limits (IG > 5 block; YT > 3 warn, > 60 block), ≥ 1 niche hashtag (warn), hashtag set identical to a recent one (warn), caption empty (block) / near-duplicate of recent (≥ 0.8 block, ≥ 0.6 warn), first line ≤ 125 chars as a hook (warn), length limits (IG 2200, TikTok 2200, YT title ≤ 100 / description 5000), duration bounds per platform, location lint (existing), duplicate video from A (passed in). Export `judgeWarnings(...)` in the existing warning shape so the lead wires it into warnings.ts with one call. Tests per check.
- Weekly caption refresh: a one-shot script `pnpm skill:recaption --week <monday> [--apply]` that re-composes captions for DRAFT items of a week that fail the judge (dry run prints a table). Never touches approved items.

## C. UI (designer, Sonnet) — owns apps/web/components/calendar/*, apps/web/components/studio/{ClipStrip,Timeline,TrimBar*}.tsx, apps/web/lib/studio/trim*.ts
- **Play before approve**: on every calendar post preview (PostCard thumbnail, PostHoverPreview, the Approve-all dialog rows, the item detail if any) a **play button bottom-left** on the thumbnail; tap plays inline (`ClipVideo`, `/app/media/clip/<id>`, muted toggle, tap again pauses). Approve-all dialog shows each post's thumbnail + play + its judge score chip once B lands (shape `{ score, checks }`; render blocks red, warns amber).
- **Drag-trim** (Studio): each clip gets a trim bar = a filmstrip (8–10 frames captured client-side by seeking a hidden `<video>` of `/app/media/clip/<id>` and drawing to canvas; fallback the poster) with **left/right handles** dragged by pointer (touch-action none, pointer capture); while dragging, the preview shows the frame at the handle; the kept range is highlighted, the rest dimmed; shows in/out/length; min piece length from LIMITS; numeric fields move into a collapsed "Exact times". Keyboard: handles focusable, arrows ±0.1 s.
