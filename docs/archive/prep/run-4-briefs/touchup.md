## Problems

## Decisions already made by the lead
- QA issues become **structured**: `{ code, severity: 'fix' | 'info', fixable: boolean, detail, segments? }`. `info` items are tags ("No sound yet", "Landscape"), never shown in Touch-up. Only `fix` items count as flagged.
- **Fixes run in the worker** (it is always on and can read the clean file from R2), not on the laptop. The worker image gets ffmpeg. The original is never changed or removed: a fix produces a **new media row** (`derived_from` = the original) that goes through the same strip-metadata → probe → QA → hash → poster steps as a normal ingest. He then picks "Keep the fix" or "Keep the original".
- "Keep the fix" re-points **draft** calendar items from the original to the fixed clip. Approved or handed-off items are never re-pointed (the approval was for the file he saw); the result says how many stayed.
- Legacy string warnings already stored on media rows cannot be trusted. They are re-read through a mapper: "effectively silent" → info tag `no-sound`; legacy frozen/black counts without positions → `recheck` (not flagged). A low-rate worker job re-runs the new QA on those clips from R2 and stores the structured result.

## Build
1. **Thresholds** (`packages/media/src/qa.ts`, tests first, using small synthetic clips generated in the test with ffmpeg lavfi; skip the ffmpeg-backed tests with a clear message when ffmpeg is absent, as existing tests do):
   - Frozen: `freezedetect=n=-60dB:d=2` (bit-for-bit still frames for ≥ 2 s). Flag as `frozen-head` / `frozen-tail` when a segment touches the first or last 0.5 s (fixable: trim), or `frozen-middle` only when one segment is ≥ 5 s or frozen time is > 40% of the clip (not auto-fixable: info with detail, severity 'fix' but `fixable: false`… decide: make it `info` unless > 40%, then `fix`, not fixable, text "Mostly a still image. Re-export it.").
   - Black: `blackdetect=d=0.5:pix_th=0.10`; `black-head` / `black-tail` (fixable: trim) when touching the ends; black in the middle ≥ 2 s = info.
   - Sound: no audio stream or integrated < −50 LUFS → info `no-sound`. Audio present but integrated loudness outside −14 ± 4 LUFS or true peak > −1 dBTP → `fix` `loudness` (fixable: two-pass loudnorm to −14 LUFS / −1.5 dBTP). Leading/trailing silence is not an issue. Mid-clip silence gaps ≥ 1.5 s in a clip that otherwise has speech-level audio → `info` `silence-gaps`, with an optional fix "Remove silent gaps" (off by default in bulk; it changes pacing).
   - Format: not H.264/AAC in MP4, odd dimensions, variable/odd frame rate above 60, non-yuv420p, bitrate absurdly high, rotation metadata present, not 9:16 within tolerance → `fix` `format` / `rotation` / `aspect` (fixable: re-encode H.264 high, yuv420p, AAC 48 kHz, `+faststart`, bake rotation; aspect fix = pad to 1080×1920 with blurred-background fill ONLY for near-vertical sources (4:5, 3:4); landscape stays `info` "Landscape" and is never auto-fixed).
   - Metadata: location or device metadata present → `fix` `metadata` (fixable: strip), though the normal ingest already strips; this catches stragglers.
   - Calibration test: synthetic "tripod talking head" (static background with mild sensor noise + a small moving region + speech-level tone bursts), "gym set" (periodic motion), "music-later" (silent) and "screen recording" (very static, cursor moves) clips must produce zero `fix` issues; clips with a 3 s frozen tail, a 1 s black head, −30 LUFS audio, HEVC video and rotation metadata must each produce exactly the expected `fix`.

3. **Fix engine** `packages/media/src/fix.ts` (pure arg builders tested without ffmpeg; one integration test with ffmpeg on a synthetic clip per op):
   - `planFix(qa, ops?)` → ordered ffmpeg steps for the fixable issues (trim head/tail to the detected segment bounds snapped to a keyframe-safe re-encode; loudnorm two-pass; re-encode; strip metadata always `-map_metadata -1 -map_chapters -1`, no GPS can survive; rotation bake; near-vertical pad). One output file; never overwrite the input.
   - `runFix(inputPath, outPath, plan)` → `{ before: stats, after: stats }` (duration, loudness, codec, dimensions, size).
